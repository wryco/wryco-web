Wryco.EntityFirst

Why Install Example Routes Customizing NuGet

An entity-first design pattern for ASP.NET Core. Define your entity, inherit the base layers, and get a working CRUD API in minutes.

ASP.NET Core EF Core v1.0.1 Open Source

Why?

Free, fast, easy, modular, and hackable. Extend provided base classes (BaseIEntity, BaseDbContext, BaseRepository, and BaseController) to skip repetitive CRUD boilerplate while keeping full control to override methods or drop down to custom logic whenever a route outgrows defaults.

Install

dotnet add package Wryco.EFirst --version 1.0.1

Example

Base Class Entity DbContext Repository Controller
"Create an entity."

1. Entity

public class Device : BaseIEntity
{
    // Main
    public int Id { get; set; }
    public required string Name { get; set; }

    // Meta
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    public DateTime UpdatedAt { get; set; } = DateTime.UtcNow;
    public DateTime LastActiveAt { get; set; } = DateTime.UtcNow;
}
"Reference it in your database context."

2. Context

public class ApplicationDbContext : BaseDbContext
{
    public ApplicationDbContext(DbContextOptions<ApplicationDbContext> options) : base(options) { }
    public DbSet<Device> Devices { get; set; } = null!;
}
"Give it a repository."

3. Repository

public class DeviceRepository : BaseRepository<Device>
{
    public DeviceRepository(ApplicationDbContext context) : base(context) { }
}
"Add the typical Program.cs additions."

4. Program.cs

// ...
builder.Services.AddSharedInfrastructure<ApplicationDbContext>(dbConnectionString);
builder.Services.AddScoped<DeviceRepository>();
// ...
"And make it all accessible via API."

5. Controller

[ApiController]
[Route("api/device")]
public class DeviceController : BaseController<DeviceRepository, Device>
{
    public DeviceController(DeviceRepository repository) : base(repository) { }
}

That's it.

The five steps above scaffold a working CRUD API exposing the following endpoints:

Method Endpoint Action Description
GET /api/device index Gets all devices
GET /api/device/{id} show Gets a specific device by ID
POST /api/device create Creates a new device
PUT /api/device update Updates an existing device
DELETE /api/device delete Deletes a device

Customizing & Extending

Because every layer is a standard C# class inheriting from a base type, you are never locked in: 

public class DeviceRepository : BaseRepository<Device>
{
    public DeviceRepository(ApplicationDbContext context) : base(context) { }

    public async Task<List<Device>> GetActiveAsync()
        => await _context.Devices.Where(d => d.LastActiveAt > DateTime.UtcNow.AddMinutes(-15)).ToListAsync();
}
Best fit: Rapid prototyping, internal tools, and clean CRUD microservices where you want consistent conventions up front without giving up standard ASP.NET Core and EF Core extensibility.
